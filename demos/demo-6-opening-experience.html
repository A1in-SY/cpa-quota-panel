点开面板 · 秒开与渐进加载方案对比

现状问题：点「额度面板」时，首次请求要同步等待当页全部额度查完（最多 20 条 × 逐条请求）才返回 HTML，慢时面板几十秒不出内容。下面每个方案都可点击试玩（模拟首次打开）。

已选定并落地：方案 A（秒开壳页 + 逐条懒加载）已在 management.go / dashboard.go 实现——首次打开不再同步刷新额度，缺失卡先渲染骨架，前端按 ?entry-idx=N 逐条并发填充，卡片互不阻塞。下方 C 为后端可叠加加速项，D 为巡航预热项。

服务端并发抓取 + 超时熔断 纯后端，前端零改动

把串行额度查询改成并发 worker 池（如 6），并给单条请求加超时。下面是同样 20 条、单条 1.2s 的对比（点击看进度）。

D

后台预热缓存（巡航刷新） 长期最优解之一

插件启动后后台按 TTL 节拍持续预热全量额度缓存；点开面板时基本全是缓存命中，秒开且新鲜。

怎么选

核心：把「等全部」从服务端同步阻塞里拿出来，交给客户端按需/渐进消费。

方案面板可见首屏数据交互路径实现成本结论
A · 秒开 + 逐条懒加载~0s逐卡渐进新增 ?entry-idx中✔ 已落地
B · 后台刷新 + 轮询~0s按轮次复用 partial + 轮询中✘ 空转多
C · 后端并发 + 超时仍等全部一次出无低~中✘ 需宿主超时支持
D · 后台预热缓存~0s（热）全量（热）无中✘ 冷启动仍慢
推荐组合：A + C + D~0s渐进 + 热缓存entry-idx 为主递进✔ A 先落地，C/D 后续叠加
